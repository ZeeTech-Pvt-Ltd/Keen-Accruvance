§1

Executive summary

The site looks premium and the content is genuinely good — original copy, honest risk language, real demo labelling, clean information architecture. That means the fastest wins here are technical, not content. The single biggest blocker is that the SPA has no working server-side fallback, so search engines and anyone who refreshes a deep link get 404. After that, the work is: give every real page its own title/description/canonical, ship robots.txt + sitemap.xml, add one og.png so shares look right, add Organization/WebSite/FAQ structured data, and de-duplicate the 11 homepage deep-link URLs so they stop competing with /.

What is already strong
HTTPS + HTTP→HTTPS 308 redirect ✓ · www→non-www resolves ✓ · lang="en", viewport, theme-color ✓ · one logical H1 per real page ✓ · semantic HTML, skip-link, aria ✓ · mobile-first responsive (audited 320→1280px, no overflow) ✓ · fast page (no raster images, inline SVG) ✓
What is missing (headline)
SPA fallback 404 on every inner route ✗ · robots.txt & sitemap.xml (404) ✗ · per-page titles/metas (one shared <title>) ✗ · no canonical tags ✗ · no JSON-LD ✗ · no og:image/twitter image ✗ · 11 duplicate homepage URLs ✗ · _redirects wrong host ✗

24 Crawlability
Critical		 SPA fallback missing on Vercel. Host is Vercel (Server: Vercel); public/_redirects is Netlify-only and ignored. Live: /about /signup /contact /how-it-works all → 404. No inner page is crawlable or indexable; all internal links & refreshes 404; sitemap/OG work is moot until fixed. The single most damaging issue found. Delete nothing. Add vercel.json at project root: 
{
  "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }]
}
Static files (/robots.txt, /sitemap.xml, /favicon.svg) still win because Vercel serves filesystem before rewrites. Redeploy, then re-test /about → 200. Keep _redirects only if you may move to Netlify later.
7 URL structure
Critical		 Shared page identity. Every route serves the same static <head>. Grep across src/ found no document.title, canonical, or meta handling. All 13+ URLs show one homepage title/description in the SERP; Google picks one to show, cannibalising distinct pages (About, Contact, legal) that should rank for their own queries. Add a route-level SEO helper and call it on navigation — see Phase 3/5 for the full src/seo.js code and App.jsx diff. This gives unique title, meta description, canonical and og per page, plus noindex on /thank-you.
13 Canonical
High		 No rel="canonical" anywhere — verified in source and live HTML. 11 homepage-section URLs (/how-it-works, /why-invest, /security, /faq, /features, /resources, /testimonials, /cta, /home…) render the entire homepage — byte-identical DOM. Without canonicals they become 11 near-duplicate pages competing with /. In seo.js: for home-section routes set canonical to https://keen-accruvance.com/; for real pages set canonical to their own clean URL (no trailing slash). Full code in Phase 5.
11 Sitemap
High		 /sitemap.xml → 404 (live). No discovery map for Google; new/changed pages indexed slowly; /thank-you could get indexed without sitemap-level signalling. Add public/sitemap.xml — exact file in Phase 5 (list /, /about, /contact, /signup + legal; omit /thank-you and homepage-section duplicates).
12 Robots.txt
High		 /robots.txt → 404 (live). No crawler control; can’t block /thank-you at crawl layer; Google logs a crawl warning for missing robots.txt. Add public/robots.txt — exact file in Phase 5, incl. Disallow: /thank-you and the Sitemap line.
14 Indexing
High		 /thank-you is indexable thin content and shows only after session data; also unknown URLs render the client 404 with HTTP 200 after the rewrite fix. Empty/session pages waste crawl budget and can appear as “soft 404”s in Search Console. noindex,follow for /thank-you via seo.js. Optional later: return a true 404 via serverless function for unknown paths.
16 Broken links
High		 Every internal path link 404s when requested directly (not via client-side click). Verified above. Same root cause as row 1, but worth listing separately because Google counts each as a crawl error and users hitting “open in new tab” see 404s. Resolved by the vercel.json rewrite. Then re-run a crawl (Screaming Frog free tier or Ahrefs) to confirm zero 4xx on real URLs.
15 Duplicate content
High		 11 clean-URL routes are the same full homepage DOM; plus trailing slash variants would double them after the rewrite fix. Ranking power splits across identical URLs; Google may show the wrong variant or fold unpredictably. Canonical all home-section routes → / (in seo.js). Normalise /privacy/ → /privacy in currentPath() (Phase 5 diff) so trailing-slash 404s become the right page.
1 Technical — meta
High		 Title is generic: “Keen Accruvance — AI-Powered Trading Platform” (≈49 chars) shared by all pages; no keyword differentiation, no page-name first. Titles are the #1 on-SERP decision factor; a shared title hides About/Contact/FAQ pages. Per-page titles in Phase 3 table + seo.js. Home keeps brand-first (brand queries); sub-pages lead with the page purpose.
19/20 Social meta
High		 og:image, og:url, twitter:title, twitter:description, twitter:image all missing. twitter:card=summary_large_image points at an image that doesn’t exist. Links shared on WhatsApp/Twitter/LinkedIn render with no image or wrong card; ugly, low-CTR shares of your best marketing surface. Create public/og.png 1200×630 (brand colours + name) and add full OG/Twitter tags in index.html — exact snippet Phase 11.
6 Schema
High		 No structured data (no application/ld+json anywhere). No rich results, no brand knowledge-panel hooks, no FAQ rich snippets; you lose SERP real estate and E-E-A-T signals. Add Organization + WebSite JSON-LD in index.html and FAQPage on the homepage route — full code Phase 6.
2 On-page — H1
Medium		 Homepage H1 = “Smarter Trading. Powered by AI.” — emotive, but doesn’t state what Keen Accruvance is; inner routes inherit it because they’re the homepage. A crawler should infer the topic (AI trading platform) from the H1. The visual design is strong — keep it, but back it with real page-level signals below the fold and schema. Keep the H1 (brand/design call). Add service-topic H2s and Organization schema to carry the meaning. For future real sub-pages, give each its own descriptive H1.
22 Heading structure
Medium		 Homepage stacks h2 per section with h3 cards — clean. On /about, /contact, legal pages: one h1 then h2s — clean. No skipped levels found. Good hierarchy is an E-E-A-T/readability signal; skipping levels or multiple H1s hurts. No change needed on structure — keep one H1 per real page. When you add FAQ schema, mirror it with visible h3 question headings (already done in the FAQ accordion).
9 Image SEO
Medium		 No raster <img> on the site (inline SVG charts + one favicon.svg). No social share image exists as a file. Great for speed (nothing to lazy-load); the only real gap is the missing OG image (see row above) and a favicon-only identity. Add og.png (1200×630) and optional apple-touch-icon.png (180×180). No lazy-loading/WebP work needed because there are no bitmap images.
18 HTTPS/security
Low		 HTTPS ✓, 308 redirect ✓, HSTS/security headers not verified; Vercel defaults fine but unset. HTTPS is a ranking signal and trust gate; hard-to-miss security headers add E-E-A-T and safety signals. Optional: add headers to vercel.json (HSTS, X-Content-Type-Options, X-Frame-Options, Referrer-Policy). Code in Phase 5.
17 Redirects / slash
Low		 /privacy/ (trailing slash) → 404 today; after the rewrite it becomes a client 404 soft-page. Inconsistent URL variants fragment links and crawl paths. Normalise trailing slash in currentPath() (Phase 5). www/non-www already resolves — no action.
8 Performance
Low		 No images, display=swap fonts, preconnects present, small CSS. Single JS bundle (no route-level code splitting). No field data yet. Already light; bundle splitting helps on slow 4G but isn’t urgent for a marketing page. Verify with Lighthouse + CrUX once indexed. Optional later: React.lazy for chrome-less/legal routes. Do not over-optimise now.
23 JS rendering
Low		 Content is client-rendered; Google executes JS and will index it, but title/meta are set only in static HTML until seo.js is added. Client-rendered SPA titles can lag behind or be misread without per-route tags; secondary crawlers (Bing, social scrapers) may see only the shell. Route meta via seo.js (Phase 5). If you later want robust rendering for all crawlers, evaluate Vite prerender or Vercel Edge rendering — Phase 5 “optional” note.
21 Accessibility→SEO
Low		 Skip-link ✓, focus styles ✓, aria-expanded on FAQ ✓, form labels ✓. Colour-contrast of small muted text is borderline on some sections. Accessibility is a quality/E-E-A-T signal and required for inclusive UX; borderline contrast also reduces readability (a UX ranking factor). No structural fix required. If you restyle later, keep body text ≥ #5c6f68-dark on light and run axe once.
25 GSC readiness
Low		 No evidence of Search Console verification, sitemap submission, or indexing history. You’re flying blind on queries, CTR, Core Web Vitals and index coverage. Full 12-step GSC onboarding in Phase 12.
3/4 Content SEO
Medium		 Copy is high-quality but no page has substantial body copy optimised for search intent; services are described in sections, not as crawlable informational/transactional text with headings. Legal pages exist but /about is short. For a brand-new domain there is almost no non-brand organic query the site can win until there is real topical text. See Phase 7: add honest service/education copy (not keyword stuffing) and a small evergreen blog/guides section later as the growth engine.
10 Favicon
Low		 favicon.svg exists and is linked ✓. No PNG fallback for older crawlers/browsers. SVG favicons are fine in modern browsers; a PNG fallback helps a few legacy contexts and social/OS touch icons. Optional: add <link rel="icon" href="/favicon.svg" type="image/svg+xml"> + <link rel="apple-touch-icon" href="/apple-touch-icon.png">.

function setMeta(selector, attr, value) {
  let el = document.head.querySelector(selector)
  if (!el) { el = document.createElement('meta'); el.setAttribute(attr, ''); document.head.appendChild(el) }
  if (attr === 'content') el.setAttribute('content', value)
  el.setAttribute(attr, value)
}
function upsertMeta(name, content) {
  let el = document.head.querySelector(`meta[name="${name}"]`)
  if (!el) { el = document.createElement('meta'); el.name = name; document.head.appendChild(el) }
  el.content = content
}
function upsertLink(rel, href) {
  let el = document.head.querySelector(`link[rel="${rel}"]`)
  if (!el) { el = document.createElement('link'); el.rel = rel; document.head.appendChild(el) }
  el.href = href
}

export function applyRouteSeo(path) {
  const key = ROUTE_SEO[path]
  const isHomeSection = HOME_SECTIONS.includes(path.replace(/^\//, ''))
  const cfg = key || (isHomeSection ? ROUTE_SEO['/'] : null)

  // Unknown paths → keep safe, noindex them
  if (!cfg) { upsertMeta('robots', 'noindex, follow'); return }

  document.title = cfg.title
  upsertMeta('description', cfg.description)
  upsertMeta('robots', NOINDEX.includes(path) ? 'noindex, follow' : 'index, follow')

  // Canonical: section deep-links fold into /; real pages canonicalise to themselves
  const canonical = SITE + (isHomeSection ? '/' : path)
  upsertLink('canonical', canonical)
  // Keep social tags in sync (og:url / og:title)
  let og = document.head.querySelector('meta[property="og:url"]')
  if (!og) { og = document.createElement('meta'); og.setAttribute('property', 'og:url'); document.head.appendChild(og) }
  og.setAttribute('content', canonical)
}
